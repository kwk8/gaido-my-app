# ラック搭載図・電力集計の運用

機器台帳（1行=1機器）を正本にして、搭載図と電力集計を自動で追随させる仕組みです。
図形をドラッグする作業と、電力を手で足し込む作業をなくします。

## 2 つの作り方

この資料は Teams のチャネル（＝SharePoint のドキュメントライブラリ）に置き、機器を入れ替えた人が
その都度ブラウザの Excel で直す運用です。そのため**普段使うのは Excel だけで完結する台帳版**です。
Python スクリプトは、移行と、drawio 形式の図が要るときにだけ使います。

| | 使うもの | いつ使うか |
|---|---|---|
| **台帳版ブック**（`build_shared_workbook.py` が生成） | Excel だけ。数式で搭載図・集計・点検まで動く | **普段の更新。SharePoint に置いて全員で直す** |
| drawio 版（`build_rack_outputs.py`） | Python + drawio | 工事図面として drawio / PNG が要るとき |

台帳版ブックは図形を 1 つも使いません。図形が入ったブックは同時編集で競合しやすいため、
共同編集する資料からは外しています。

## 何が変わるか

| | これまで | この仕組み |
|---|---|---|
| 機器を動かす | 前面と背面の図形を 2 か所ドラッグし、電力欄の行も手で合わせる | 台帳の「開始U」を書き換える（1 か所） |
| 2U 以上の機器 | U の行数ぶん行を占め、電力をどの行に書くか決まりがない | 「U数」に 2 以上を入れる。行は 1 行のまま |
| 電力の合計 | 手入力の消費電力を SUM する。式が壊れても気づかない | 電圧×電流から毎回計算し直す |
| 記入漏れ | 気づかない | 点検結果に出て、図にも赤い破線で出る |
| 回路の余裕 | 判定する欄がない | 片系実効値がブレーカ定格の 80% を超えたら警告 |

## 台帳版ブックを作る（移行時に 1 回）

```bash
python3 extract_ledger.py "<元の実装図.xlsx>" \
    --out-json ../../ai_generated/rack/ledger.json \
    --out-csv  ../../ai_generated/rack/ledger.csv
python3 build_shared_workbook.py \
    --ledger-json ../../ai_generated/rack/ledger.json \
    --out "../../ai_generated/rack/ラック搭載図_台帳版.xlsx"
```

できたブックを SharePoint へ置けば、以降は Excel だけで回ります。中身は
使い方 / 機器台帳 / ラック定義 / 回路定義 / 搭載図 / 電力集計 の 6 シートです。

- 「搭載図」は `INDEX` と `MATCH` で台帳を引いています（配列数式ではないため Ctrl+Shift+Enter は不要）
- `TEXTJOIN` など新しい関数は使っていません。古い Excel でも `#NAME?` になりません
- 用途による色分けと、電力未記入の赤字は条件付き書式です

## drawio 版を作る（図面が要るときだけ）

```bash
# 1. （移行時だけ）元の実装図 Excel から台帳を起こす
python3 extract_ledger.py "<元の実装図.xlsx>" \
    --out-json ../../ai_generated/rack/ledger.json \
    --out-csv  ../../ai_generated/rack/ledger.csv
python3 build_ledger_xlsx.py \
    --ledger-json ../../ai_generated/rack/ledger.json \
    --out ../../ai_generated/rack/rack_ledger.xlsx

# 2. 台帳（rack_ledger.xlsx）を編集する ← 普段はここだけ

# 3. 図と集計を作り直す
python3 build_rack_outputs.py \
    --ledger ../../ai_generated/rack/rack_ledger.xlsx \
    --out-dir ../../ai_generated/rack/out --png

# 4. （並行運用の間だけ）元の Excel と値が合っているか確かめる
python3 reconcile.py --original "<元の実装図.xlsx>" \
    --ledger ../../ai_generated/rack/rack_ledger.xlsx \
    --out ../../ai_generated/rack/reconcile.md
```

`--png` を外すと drawio だけを作ります（PNG 化は 1 ラックあたり数十秒かかります）。

## 台帳の中身

`rack_ledger.xlsx` は 3 枚のシートでできています。

- **機器台帳**: 1 行 1 機器。開始U・U数・機器名・資産番号・電力・重量を持ちます
- **ラック定義**: ラックごとの総U・回路（電圧・ブレーカ容量）・需要率・警告閾値
- **使い方**: 記入のきまり

### 電力の書き方

電流は「その回路が受け持つ電流」を入れます。1 台が 2 回路に繋がるなら回路1・回路2 に分けます。
消費電力 W は `電圧 × 電流の合計` で計算するため、台帳には持ちません（二重入力をなくすためです）。

### 判定のしかた

- **両系実効値**: 正常時。機器の負荷が繋がっている回路の数で等分されるとみなします
- **片系実効値**: 片方の回路が落ちたとき。残った回路がその機器の全負荷を受けます
- どちらも需要率（既定 0.6）を掛けます。**片系実効値がブレーカ定格の 80% を超えたら「要対応」**とします

需要率と閾値は「ラック定義」シートで変えられます。式に埋め込んでいません。

## 出てくるもの

| ファイル | 中身 |
|---|---|
| `<ラック名>_搭載図.drawio` | 前面図・背面図と、寸法・重量・電力・回路判定を書いた注記 |
| `<ラック名>_搭載図.png` | 上を画像にしたもの |
| `power_summary.xlsx` | 「電力集計」＝回路ごとの定格・両系・片系・判定、「点検結果」＝要対応と参考 |

図は毎回作り直します。**図を直接編集しないでください**（次の生成で消えます）。直すのは台帳です。

## 図の読み方

- 色は用途（青=Server / 橙=Storage / 緑=SW / 赤=PDU / 灰=非電源品）
- **赤い破線** = 電力が未記入で、集計に入っていない機器
- **灰の破線** = 備考で電源オフとされている機器（意図的とみなし、要対応にしません）
- 同じ U に複数台あるときは横に並べます（1U に 2 台載せる小型機器のため）

## 取り込みで気をつけること

元の Excel は、機器名を①〜⑤が浮動図形・⑥がセルで持っていました。`extract_ledger.py` は
両方を読みます。取り込み時に次を報告するので、内容を確認してください。

- 前面と背面で U 位置が違う機器（前面の位置を採用します）
- 電力の記入はあるが機器が描かれていない行（負荷を落とさないよう「要確認」の行として残します）
- `100V` `1系統` のような単位付き文字列を数値へ読み替えた箇所
