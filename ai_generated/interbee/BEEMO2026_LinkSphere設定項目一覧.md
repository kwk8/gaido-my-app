## 3. TBS 回線センター Spine（tbs-b-spine-sw）

### 3.1 ポート設定

収容図 p.2「メディア面（Blue）: LinkSphere D6848Y8C」と p.1「共通基盤 Spine LinkSphere CTC」から読みました。
ポート番号は収容図の番号です。49〜56 は 100GE（QSFP28）の 1〜8 番目にあたります。

| ポート | 速度・光 | 接続先 | 種別 | IP アドレス（/30） | 出典 |
|---|---|---|---|---|---|
| 1 | 10GbE/SR | 名古屋用ルーター NE8000-F1A の port 26 | Routed | 10.0.22.4/30 のどちらか | 収容図 p.1・p.2、全体会資料 p.13 |
| 49 | 100GbE/LR4 | ヘキサゴン Leaf LinkSphere の port 56 | Routed | 10.0.20.0/30 のどちらか | 収容図 p.2・p.5、全体会資料 p.10 |
| 55 | 100GbE/LR4 | 回線集約SW FS-AX3660S-48X4QW の port 50（大阪向け） | Routed | 10.0.22.0/30 のどちらか | 収容図 p.1・p.2、全体会資料 p.13 |
| 56 | 100GbE/LR4 | WDM PL-2000ADS（幕張向け） | Routed | 10.0.21.0/30 のどちらか | 収容図 p.2、全体会資料 p.14 |
| 管理 | 1GbE/RJ-45 | FortiGate-200G の port 2 | 管理 | 172.16.5.XXX/16 | 収容図 p.1、IP表 |

ポート 1 は SFP28（25G）のポートに 10G の光モジュールを挿します。ポートの速度を 10G に合わせる設定が要ります。

### 3.2 ルーティング

| 接続先 | プロトコル | 出典 |
|---|---|---|
| 幕張 Media SW(B)（YAMAHA）、10.0.21.0/30 | OSPF | 全体会資料 p.14 |
| ヘキサゴン Leaf、10.0.20.0/30 | 記載なし（OSPF が自然。要確認） | 全体会資料 p.10 |
| 大阪 SW（ARISTA）、10.0.22.0/30（回線集約SW の VLAN2200 経由、回線内で tag → untag） | 記載なし（要確認） | 全体会資料 p.13 |
| 名古屋ルーター（HUAWEI）、10.0.22.4/30（名古屋側は GRE で延伸） | 記載なし（要確認） | 全体会資料 p.13 |

経路で運ぶネットワーク（全体会資料 p.10・p.13・p.15 から）:

- ヘキサゴン: 10.218.0.0/16、10.219.0.0/16（企画①の 10.216.0.0/16 は Amber の Arista 側に集約されている図のため要確認）
- 大阪: 10.200.0.0/16
- 名古屋: 10.202.0.0/16
- 幕張: 10.214.0.0/16、10.215.0.0/16

### 3.3 マルチキャスト

- 全ての Routed ポートで PIM を有効にします（拠点をまたぐ映像・音声の転送のため）
- SSM の範囲 232.0.0.0/8 を使います（IP表「マルチキャストアドレス記入表」）
- ASM（239.x）を使うなら RP（ランデブーポイント）が要ります。RP の置き場所は資料に記載がありません

### 3.4 PTP

PTP案と全体会資料 p.16 に「PTP の配信範囲は各拠点に限る」とあります。共通基盤には GM（グランドマスター）がありません。
このため Spine では PTP を使わない（各ポートで PTP を通さない）のが自然です。一方、PTP案の基本パラメーターには「対象スイッチ: PTP、Spine、Leaf」とあり、食い違います（7 章で確認）。

### 4.2 Vbus 向けの VLAN 設定（全体会資料 p.11・p.12）

Videotron Vbus-70V2 の 4 台は、メディアの IP と管理（インバンド管理）を 1 本のポートで流します。「メディア面 VLAN は Native（Untag）で渡す」と書かれています。

| ポート | 機器（収容図の表記） | Untag（PVID） | Tag | VLANIF の IP |
|---|---|---|---|---|
| 3 | IPVT-70U① | VLAN2191 | VLAN19 | 10.219.23.1/30 |
| 4 | IPCK-70U② | VLAN2192 | VLAN19 | 10.219.23.5/30 |
| 5 | IPVT-70H① | VLAN2193 | VLAN19 | 10.219.23.9/30 |
| 6 | IPCK-70H② | VLAN2194 | VLAN19 | 10.219.23.13/30 |

- VLAN19（172.19.0.0/16）は、LinkSphere では L2 で通すだけです（IP は持たせない）。管理SW（FortiSwitch）へ Access ポートで渡します（全体会資料 p.11 の「Media SW(B) → Access → Mgmt SW VLAN19」）
- 全体会資料 p.11・p.12 の VLAN2192「10.219.23.4/16」と VLAN2194「10.219.23.12/16」は /30 の誤記と読みました（IP表は 255.255.255.252）

### 4.3 ルーティング

- Spine 向け 10.0.20.0/30（port 56）で、10.218.0.0/16 と 10.219.0.0/16 を広告します
- 端末ごとの /30（4.1 の表）は、Leaf では直結のネットワークです。そのまま広告するか、/16 にまとめて広告するかを決めます
- プロトコルは資料に記載がありません（幕張との間は OSPF のため、OSPF が自然。要確認）

### 4.4 マルチキャスト

| 項目 | 内容 | 出典 |
|---|---|---|
| 端末向けポート | IGMP（SSM を使うため v3）を有効にする | IP表のマルチキャスト記入表（SSM: 232.219.<ベンダーID>.x） |
| Spine 向けポート | PIM を有効にする | 拠点間の転送のため |
| SSM の範囲 | 232.0.0.0/8（企画③ Blue は 232.219.x.x） | IP表 |
| ASM の範囲 | 239.219.x.x（企画③ Blue）。使うなら RP が要る | IP表 |
| 届いている送出の例 | Viz FILL1〜3 / KEY1〜3（232.219.24.x）、Vbus 企画2/3 の映像・音声・ANC（232.219.23.x） | IP表のマルチキャスト記入表 |

第 4 オクテットの範囲は 1〜99 が映像、100〜199 が音声、200〜254 が ANC です。

### 4.5 PTP

PTP案と全体会資料 p.18・p.19 の値です。

| 項目 | 値 |
|---|---|
| 動作モード | BC（Boundary Clock） |
| プロファイル | SMPTE ST 2059-2 / AES67 |
| プロトコル | IPv4 UDP |
| タイムスタンプの送信方式 | Two Step |
| 遅延測定 | E2E（Delay Request-Response） |
| ドメイン番号 | 0 |
| Priority1 / Priority2 | **20 / 22**（Media SW(B) = Blue） |
| Delay_Req / Delay_Resp の通信方式 | Multicast |
| Announce の送信間隔 | -2（4 pkt/s） |
| Announce の受信タイムアウト | 3（資料は「3 sec」。間隔 -2 の 3 回分なら 0.75 秒になるため単位を要確認） |
| Sync の送信間隔 | -3（8 pkt/s） |
| Delay Request の送信間隔 | -3（8 pkt/s） |

PTP を有効にするポート:

- 47（GM: TS-2950、Priority 1/2）
- 48（Amber Leaf との BMCA 用リンク。相手側の GM を予備として見るためのリンク）
- 端末向けのポート（3〜8、33、41、42、51〜53。SNE-X は用途しだい）

PTP を有効にしないポート: 56（Spine 向け。PTP は拠点内に限るため）

## 5. 設定しないもの・他の担当のもの

- 回線集約SW（FS-AX3660S）の VLAN2200、名古屋ルーターの GRE、WDM: それぞれの担当です
- 管理面（VLAN19・VLAN18・VLAN31）のゲートウェイ（172.19.255.254 など）: FortiGate / FortiSwitch 側です
- Amber 面（10.119.x、10.0.10.0/30 など）: ARISTA 側です。Blue と Amber は、BMCA 用リンク（port 48）以外で直接つなぎません
